## 一、为什么会有这一轮查漏补缺

前面的内容我是一边看任务书一边做的，做完之后感觉「功能都跑通了」。
但在正式提交前，我换了一种方式复核：**把任务书逐句拆成"可验收的条目"**——
判断标准是：一条要求必须能对应到具体的文件、图或表格，否则就等于没做。

拆完一共 **41 个可验收条目**，逐条核对的结果是：

| 板块 | 完全满足 | 部分满足 | 缺失 | 加权完成度 |
|---|---|---|---|---|
| 一、环境准备 | 3 | 0 | 0 | 100% |
| 二、个人简介 | 3 | 0 | 1 | 75% |
| 三、通用素养 | 6 | 1 | 0 | 92.9% |
| **四、小游戏（贪吃蛇）** | 4 | 2 | **5** | **45.5%** |
| 五、进阶挑战 · 通用 | 3 | 2 | 0 | 80% |
| **① RC 低通滤波** | 0 | 2 | **2** | **25%** |
| ② 戴维南验证 | 1 | 2 | 0 | 66.7% |
| ③ NMOS 共源放大 | 2 | 2 | 0 | 75% |
| **合计** | **22** | **11** | **8** | **67.1%** |

也就是说：**"功能都跑通了"不等于"要求都落实了"。** 有些要求我读的时候自己脑补成了
别的意思，有些是我以为做了其实没做，还有几处是做了但没有在 README 里呈现出来
（图没插入、网址没写）——**文件躺在仓库里但没被引用，等于没交付。**

最刺眼的是两处：**小游戏板块只有 45.5%**（任务书要求"至少实现 1 个新增功能"，我一个都没做），
**RC 电路只有 25%**（任务书明确要求"方波输入/输出瞬态波形图"和"τ、截止频率的手算 vs 仿真表"，
我两样都没有）。

下面把所有缺口按任务书条款列清楚。

  「重置全部纪录」才会清空最高分、局数和战绩，点「重新开始」只重开一局，纪录保留。
  这就是原来缺的那两个点：**局数**和**真正的重置**（原来那个按钮是"重新开始"，不是"重置"）。
- **主题切换（对齐验收标准）**：≥2 套配色、一键切换即时生效、**刷新后保留**（写进 localStorage）。

这是整轮查漏补缺里技术含量最高的一处，我把它单独写成了 `snake_core.js`，理由见第四节。

**A4 补截图**：用无头浏览器对页面截图，把游戏界面、AI 运行画面插入 README。

### D 组：戴维南

- **D1**：新增短路电流仿真：把输出端口短路，用 0V 电压源当电流表测 I_sc；
  同时用等效电路测一次，验证 `I_sc = V_th / R_th`。
- **D2**：负载验证表补上**电流**列（原电路与等效电路各测一次）。

### E 组：NMOS（我认为这组是这一轮最有价值的修改）

**E1 把归因改对。** 关键认识是：**SPICE Level 1 的漏电流公式本身就是
`I_D = (K/2)(V_GS - V_th)²(1 + λV_DS)`**，我手算时只用了前一半。把 λ 项补回来后，
`I_D` 和 `V_DS` 变成一组联立方程（因为 `V_DS = VDD - I_D·R_D`），迭代求解得到：

| 量 | 原手算（漏 λ） | 补 λ 后自洽解 | 仿真值 |
|---|---|---|---|
| I_D | 0.4000 mA | 0.4331 mA | — |
| V_DS | 4.2000 V | **4.1339 V** | **4.1339 V** |
| gm | 0.8000 mS | 0.8661 mS | 见表格 |
| Av | -1.5748 | **-1.7028** | **-1.7050** |

误差从 8% 降到 **0.13%**。所以那 8% 不是"模型不完整"，是**我的手算少了一项**。
这个纠错过程本身就是一次很好的模拟电路训练。

**E2 把负号找回来。** 增益统一写成 **Av = -gm(R_D ∥ r_o)**，并在图里给出反相的直接证据：
输入正弦与输出正弦的峰值在时间上错开半个周期，输出与输入反相 180°。

**E3** 补 gm 的仿真测量值，与手算并列对比。

## 四、为什么把贪吃蛇逻辑拆成 `snake_core.js`

原来的 `snake.html` 把游戏逻辑、绘制、事件处理全揉在一个 `<script>` 里。这次要验证
"AI 能不能稳定吃到 15 个"，如果逻辑只存在于 HTML 里，我就只能**靠手动玩很多局去数**，
既没法给出统计结论，也没法保证"我测的"和"演示的"是同一份代码。

所以拆成三层：

```
snake_core.js   纯逻辑：状态机 + 移动规则 + 两套 AI 算法（不碰 DOM，浏览器和 Node 都能跑）
snake_store.js  纯存储：最高分 / 局数 / 最近 10 局 / 主题（localStorage 的封装）
snake.html      界面：绘制、事件、定时循环，引用上面两个文件
```

好处是 `snake_core.js` 可以直接被 Node 的测试脚本 `require()`：

```
node audit/snake_ai_test.js 300
```

于是"AI 达标率"变成一个**可复现的数字**，而不是"我玩了几次都没死"。这是我从这次查漏补缺里
学到的最大一点：**能被测量的东西才谈得上验证。**

顺带一个发现：调 `spaceFactor`（安全空间阈值）从 1.0 到 1.5，达标率**完全一样**（都是 299/300）。
说明失败那一局不是"保守度不够"导致的，而是追尾保命状态下的一步误判——参数不敏感这个结论
本身也值得记录，因为它排除了"靠调参凑数"的嫌疑。

## 五、查漏补缺过程中 AI 给的、我查证后认为是错误的说法（补充记录）

任务书要求记录一条，这里补充本轮新发现的**两条**，都附了查证方式：

**记录一（原有，补充查证过程）**：AI 生成的最高分功能里，`moveSnake()` 调用了
`getHighScore()` / `setHighScore()`，但没有定义这两个函数，页面报
`Uncaught ReferenceError: getHighScore is not defined`。

- **查证方式**：打开浏览器开发者工具 Console 看到完整报错和行号 → 在源文件里搜索
  `function getHighScore` 确认确实不存在 → 判断是"调用了未定义的函数"而不是逻辑错误。
- **根因**：AI 分两次生成了"读取显示"和"更新写入"两段代码，第二次生成时改动了调用处，
  但没有同步补上函数定义。
- **修正**：补上两个用 `localStorage` 读写的函数，并用 `parseInt(x, 10)` 处理取出的字符串。

**记录二（本轮新增）**：AI 在解释 NMOS 那 8% 误差时说「SPICE 模型包含更完整的效应」。
我当时接受了这个解释，但**它是错的**。

- **查证方式**：翻 SPICE Level 1（Shichman-Hodges）模型的电流方程，发现它用的就是
  `I_D = (K/2)(V_GS-V_th)²(1+λV_DS)`，而这个 λ 项正是我手算时漏掉的；把 λ 代回去联立
  求解，`V_DS` 算得 4.1339 V，与仿真输出**完全一致**。
- **根因**：AI 给了一个听起来合理但不可验证的归因（"模型更完整"），把一个具体的
  手算缺项说成了模型差异。**它没有去检查我的式子，只是在为数字差异找一个说法。**
- **教训**：遇到"理论和仿真不一致"，不能接受"模型更复杂"这种模糊归因，要回到公式本身
  逐项核对。**误差是线索，不是结论。**

**记录三（本轮新增）**：AI 一开始给我的 BFS 寻路代码里，把"目标格"也放进了障碍集合，
导致"食物恰好是蛇尾所在格"时搜不到路径。

- **查证方式**：批量测试时发现有个别局数分数异常低，单独复跑打印每步状态，看到 AI 明明
  与食物相邻却进入了"追尾保命"分支。
- **根因**：BFS 的障碍判断没有对起点/终点做例外处理。
- **修正**：BFS 里显式规定**起点和终点永远可通行**，障碍集合只约束中间格。

> 一句话交代：**AI 帮我写代码和排版，公式推导、需求拆解、以及对结果的怀疑和验证是我自己做的。**

## 八、分批提交的建议

这一轮改动**不要压成一个提交**，按主题分 5 批，这样在提交历史里也能看出
"先补呈现 → 再做硬指标 → 再补电路 → 再修结论 → 最后写文档"的顺序：

| 批次 | 提交内容 | 对应任务书条款 | 提交信息建议 |
|---|---|---|---|
| 1 | README 重排（补网址、项目说明）+ `screenshots/` | 二、六 | `README补充网站地址与项目说明，加入界面截图` |
| 2 | 贪吃蛇重写：CSS、两套主题、计分制（含局数/重置）、最近 10 局战绩 | 四·作品要求 | `贪吃蛇补齐样式与新增功能：主题切换、局数统计、重置、多局战绩` |
| 3 | 抽出 `snake_core.js` / `snake_store.js`，BFS 智能 AI，`audit/` 测试脚本 | 四·阶段二 | `贪吃蛇AI改为BFS最短路+安全性校验，加入批量达标率测试` |
| 4 | RC 瞬态与波特图、戴维南 I_sc 与电流验证、NMOS λ 修正 | 五·电路①②③ | 可拆成三个提交，各自说明补了什么 |
| 5 | `docs/` 两份文档 + README 的 AI 错误记录补充 | 三·素养、六 | `补充AI错误查证记录与查漏补缺说明` |

**每一条提交信息都要写"补了什么"，不要写"修改文件"。**
提交历史本身就是"我确实做过一遍自检"的证据。
